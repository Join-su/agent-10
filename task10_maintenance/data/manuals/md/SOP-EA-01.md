# 설비 이상 이벤트 대응 표준 절차서

> 가상 문서(synthetic_manual) — 과제 10 학습용으로 만든 절차서입니다. 실제 사업장의 절차가 아닙니다.

## 1. 목적과 범위

이 절차서는 고장 예측 모델이 만든 이상 이벤트(EventCard)를 받았을 때 확인·판단·보고하는 순서를 정합니다. 대상 설비는 MC-01입니다. 고장 유형별 점검 방법은 **MC-01 정비 매뉴얼(MC01-MM)** 4장을 따릅니다.

이 절차의 결과물은 **원인 후보와 점검 절차 초안**, 그리고 **정비 보고서**입니다. 원인을 확정하거나 설비를 직접 제어하는 것은 이 절차의 범위가 아닙니다.

## 2. 역할

| 역할 | 책임 |
|---|---|
| 운전자 | 이벤트 발생 시 가공을 멈출지 판단하고 정비 기술자를 부른다 |
| 정비 기술자 | 매뉴얼에 따라 점검·조치하고 보고서를 작성한다 |
| 정비 엔지니어 | escalation 된 건을 판단하고 원인을 확정한다 |
| 품질 담당 | 고장 시점 전후 가공품의 격리와 재검사를 결정한다 |
| 이상 대응 지원 Agent | 근거를 모아 원인 후보·점검 절차 초안·보고서 초안을 만든다. 결정하지 않는다 |

## 3. 이벤트 접수

EventCard를 받으면 다음 항목을 먼저 확인합니다.

1. **설비와 시각**: equipment_id, detected_at
2. **센서 값**: sensor_snapshot 의 다섯 값과 파생 값 두 개(온도 차, 기계 출력)
3. **예측**: predicted_failure_type, probabilities, confidence_level
4. **복합 여부**: candidates 에 유형이 두 개 이상이면 복합 의심입니다
5. **근거 신호**: top_signals 가 매뉴얼 판정 기준과 같은 방향인지

EventCard의 예측은 확정이 아닙니다. 모델이 잘 맞히지 못하는 유형과 한계는 **ML-GUIDE-01**에 있습니다.

## 4. 확신도별 대응

| confidence_level | severity | 대응 시간 | 대응 |
|---|---|---|---|
| high (0.8 이상) | alarm | 15분 안 | 가공 일시 정지 후 해당 유형 점검 절차 착수 |
| medium (0.5 ~ 0.8) | alarm | 30분 안 | 현재 가공품 완료 후 점검. 매뉴얼 판정 기준으로 재확인 |
| low (0.5 미만) | warning | 교대 안 | 가공 유지. 판정 기준과 이력을 확인하고 점검 필요 여부 판단 |

공구 마모 고장(TWF)은 모델 확률이 낮게 나오는 유형이라 0.10 이상이면 경고를 냅니다. TWF 경고는 확률보다 **공구 마모 시간**과 **마지막 공구 교체 기록**으로 판단합니다(MC01-MM 4.1.3).

## 5. 근거 확인

### 5.1 매뉴얼 판정 기준 재확인

예측 유형의 판정 기준(MC01-MM 부록 A)에 센서 값을 넣어 다시 확인합니다.

- 판정 기준에 해당하면: 해당 유형의 점검 절차를 따릅니다.
- 예측 유형의 기준에는 해당하지 않고 다른 유형의 기준에 해당하면: 예측과 센서 값이 불일치하는 것입니다(ESC-3).
- 어떤 기준에도 해당하지 않으면: 경고(warning)는 오탐 가능성을 검토하고(8장), 경보(alarm)는 escalation 합니다(ESC-7).

공구 마모 고장(TWF)의 기준은 공구 마모 200분 이상입니다. 200 ~ 240분은 위험 구간, 240분 초과는 사용 한계 초과입니다(MC01-MM 4.1.2).

### 5.2 정비 이력 조회

정비 이력에서 다음을 찾아 근거로 붙입니다.

1. **같은 유형의 최근 기록 3건**: 그때의 증상, 조치, 교체 부품, 소요 시간
2. **센서 값이 가까운 기록**: 같은 품질 등급에서 센서 값 차이가 작은 기록
3. **같은 조건의 과거 오탐 기록**(record_type: false_alarm_check): 같은 예측 유형으로 점검했는데 이상이 없었던 기록
4. **마지막 공구 교체 기록**: 공구 마모 시간 판단에 필요합니다

이력은 참고 근거입니다. 과거에 같은 조치로 해결됐다고 해서 이번에도 같은 원인이라고 단정하지 않습니다.

### 5.3 근거 인용 규칙

- 초안의 모든 원인 후보와 점검 단계에는 근거 ID를 붙입니다. 매뉴얼은 `문서 ID + 절 번호`(예: MC01-MM 4.2.3), 이력은 `record_id`(예: MR-0123)로 적습니다.
- 근거가 없는 내용은 초안에 쓰지 않습니다.
- 매뉴얼과 이력이 서로 다른 조치를 말하면 둘 다 적고 차이를 표시합니다.

## 6. 작업 중지와 escalation 기준

다음 중 하나라도 해당하면 초안을 완성하지 말고 정비 엔지니어에게 넘깁니다.

| 코드 | 조건 | 확인 방법 |
|---|---|---|
| ESC-1 | 어떤 판정 기준에도 해당하지 않는데 실제 정지가 발생했다(RNF·원인 미상) | 현장 확인 |
| ESC-2 | candidates 에 유형이 두 개 이상이다(복합 고장, MC01-MM 4.6) | EventCard |
| ESC-3 | 예측 유형의 판정 기준에는 해당하지 않고 다른 유형의 기준에 해당한다 | 판정 기준 계산 |
| ESC-4 | 근거(매뉴얼 절 또는 이력)가 하나도 없다 | 근거 조회 결과 |
| ESC-5 | 같은 유형을 조치한 뒤 24시간 안에 같은 유형의 이벤트가 다시 발생했다(조치 후 재발). 조치 전에 경보가 연달아 오는 것은 재발이 아니다 | 최근 조치 완료 기록 |
| ESC-6 | 전원 계통 이상(입력 전압 이탈)이나 누설·연기·타는 냄새가 있다 | 현장 확인 |
| ESC-7 | 경보(alarm)인데 어떤 판정 기준에도 해당하지 않는다 | 판정 기준 계산 |

escalation 기록에는 조건 코드, EventCard ID, 확인한 근거 ID를 남깁니다. ESC-1과 ESC-6은 현장에서만 확인할 수 있으므로 이상 대응 지원 Agent가 판단하지 않습니다.

## 7. 정비 보고서

### 7.1 보고서 항목

| 항목 | 내용 |
|---|---|
| 이벤트 | EventCard ID, 설비, 감지 시각 |
| 예측 | 예측 유형, 확률, 확신도 |
| 판정 | 매뉴얼 판정 기준 확인 결과 |
| 원인 후보 | 우선순위 순, 각 후보의 근거 ID |
| 점검·조치 | 수행한 단계, 교체 부품 번호, 소요 시간 |
| 결과 | 재가동 여부, 시운전 결과 |
| escalation | 해당 시 사유와 담당자 |
| 작성 | 작성자 역할, 검토자 역할 |

### 7.2 작성 원칙

- 원인은 "추정 원인 후보"로 적습니다. 정비 엔지니어 확인 전에는 "원인"이라고 단정하지 않습니다.
- 수치(온도 차, 출력, 부하 지수)는 계산 근거와 함께 적습니다.
- Agent가 만든 초안은 정비 기술자가 검토하고 서명해야 보고서가 됩니다.

## 8. 오탐 처리

점검 결과 이상이 없으면 오탐으로 처리합니다.

1. 매뉴얼 판정 기준에 해당하지 않음을 수치로 기록합니다.
2. 육안·청음 점검 결과를 기록합니다.
3. 정비 이력에 record_type: false_alarm_check 로 남깁니다. 같은 조건에서 오탐이 반복되면 모델 담당에게 알립니다.

오탐 기록도 근거입니다. 다음에 비슷한 조건의 이벤트가 오면 5.2의 3번 근거로 쓰입니다.

## 9. 이상 대응 지원 Agent의 처리 경로

Agent는 이벤트마다 세 경로 중 하나로 결과를 냅니다. 경로는 판정 기준 계산과 근거 조회 결과로 정해지며, Agent가 문장으로 판단하지 않습니다.

| 경로 | 조건 | 결과물 |
|---|---|---|
| grounded_draft | 판정 기준에 해당하고 escalation 조건이 없다 | 근거 ID가 붙은 원인 후보와 점검 절차 초안 |
| escalation | ESC-2, ESC-3, ESC-4, ESC-5, ESC-7 중 하나 이상에 해당한다 | 조건 코드와 확인한 근거 목록 |
| inspect_only | 어떤 판정 기준에도 해당하지 않는 경고(warning)다 | 오탐 점검 권고(8장)와 판정 기준 수치 |

어느 경로든 정비 기술자가 검토(승인·수정 요청·escalation·반려)해야 보고서가 됩니다(7.2).
